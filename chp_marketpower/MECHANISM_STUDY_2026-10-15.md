# CHP 报价影响如何转化为实际利润：6/30 节点配对实验

## 研究问题与最有价值的发现

本文关注的不是“报价使电价上升多少”这一个量，而是：**在同一物理执行方案下，凸化定价、机组反事实自调度及按申报成本计算的机会成本补偿，怎样共同改变战略报价的实际利润？** 现有 30 节点结果揭示了凸化定价层与物理执行层可以分离；6 节点结果则说明价格规则不同未必造成利润差异。两者共同界定了需要解释的机制，而非挑一个有利案例替代规律。

研究只考虑单台机组、全天统一的绝对可变成本加数 $\delta\ge0$，并用预先确定的中段基准斜率 $s_g^{ref}$ 将横轴标为 $\rho=\delta/s_g^{ref}$。这不是所有策略的最优反应，也没有模拟报价审核、收益抵扣等其他市场规则。所有利润结论对应**按申报成本计算的 lost-opportunity-cost uplift**。

## 三层对象不能互相代替

给定报价 $C_g^{rep}=C_g^{true}+\delta D_g$，有三套不同的优化对象：

1. 物理 UC 给出实际执行 $(p^{UC},u^{UC})$，其报价暴露是 $D_g^{UC}=\sum_t(p_{g,t}^{UC}-P_g^{min}u_{g,t}^{UC})$。
2. 凸化 CHP LP 给出定价最优值 $v_g(\delta)$、价格的一个最优对偶选择及凸化暴露 $D_g^{CHP}$。在可微点 $v_g'(\delta)=D_g^{CHP}$，**不是** $D_g^{UC}$。
3. 单机自调度给出 $M_g^{rep}(\lambda,\delta)=\max_{x_g\in X_g}\{\lambda_g^\top p_g-C_g^{rep}(x_g;\delta)\}$。它是计算申报 LOC uplift 的反事实机会盈余，而非实际出力。

在执行方案对单机可行、uplift 非负截断未改变数值时，结算严格满足

\[
\Pi_g^{true}=\lambda_g^\top p_g^{UC}+U_g^{rep}-C_g^{true}(x_g^{UC})
=M_g^{rep}(\lambda,\delta)+\delta D_g^{UC}. \tag{1}
\]

式 (1) 是**所声明 LOC 结算规则的恒等式，不是 CHP 独有定理**；代码逐点检查。若在同一执行 UC、同一报价、同一 uplift 定义下仅更换价格规则，则

\[
\Pi_g^{CHP}-\Pi_g^{fixed\text{-}UC\ LMP}
=M_g^{rep}(\lambda^{CHP},\delta)-M_g^{rep}(\lambda^{LMP},\delta). \tag{2}
\]

此配对是定价规则的受控反事实，不是对两套现实市场设计优劣的比较。两种规则的**增量利润**还各自以本规则的零加价利润为基线，不能把某一点的增量差误称为该点的绝对利润差。

若在某段区间所选价格路径恰为仿射、物理 UC 不变，则 $M_g^{rep}$ 是对仿射函数取上确界，因而是凸分段线性的，$\Pi_g^{true}$ 亦然。在唯一自调度最优解且可微处，有条件性的局部公式

\[
\frac{d\Pi_g^{true}}{d\delta}
=(p_g^{self})^\top\frac{d\lambda_g}{d\delta}
+D_g^{UC}-D_g^{self}. \tag{3}
\]

公式 (3) **不能**在未验证价格仿射、物理 UC 稳定及自调度选解的区间直接当作已测导数。利润的零交叉、利润折点、自调度切换、CHP 价值折点、价格选择变化是不同事件；它们没有必须重合的理论理由。

## 受控数值结果

两案例均为 PTDF 紧线路、24 小时、3 段成本，物理 UC、CHP、固定开机状态 LMP 与单机自调度均要求 COPT 最优。CHP 与 LMP 使用**同一份申报报价求出的物理 UC**，同一真实成本与同一 LOC uplift，分别以其原始对偶价格结算。所测点原始价格与既有截零后处理价格的最大差为零；这只核实这些点，不构成所有报价下价格唯一的证明。

| 案例、报价 | CHP 利润增量 USD | 配对 LMP 利润增量 USD | 物理暴露 $D^{UC}$ MWh | 凸化暴露 $D^{CHP}$ MWh |
|---|---:|---:|---:|---:|
| 6-G2，4% | +514.34 | +514.34 | 1071.55 | 1585.89 |
| 6-G2，6% | +129.99 | +129.99 | 180.54 | 993.53 |
| 6-G2，10% | +39.64 | +39.64 | 33.03 | 191.24 |
| 30-G1，40% | −1409.63 | +9245.36 | 760.10 | 717.86 |
| 30-G1，42.5% | −766.80 | +10546.91 | 760.10 | 686.65 |
| 30-G1，45% | +179.36 | +11848.45 | 760.10 | 684.94 |
| 30-G1，50% | −1054.58 | +11100.03 | 608.24 | 597.17 |

**6-G2 是必要对照。** 在所测 4%–10% 点，两价格规则的目标节点价格最多相差约 11.2 美元/MWh，然而两边的最佳申报自调度盈余 $M_g^{rep}$ 都约为零，故式 (2) 给出几乎相同的绝对与增量利润。非单调利润主要来自物理暴露 $D_g^{UC}$ 随报价大幅下降。不同价格不必然意味着不同利润。

**30-G1 是主机制案例。** 在已采样的 38%、40%、42.5%、45% 四个点上，**全系统**物理 UC 的逐小时出力与启停一致（相邻点最大出力差为浮点舍入量级）；这不排除未采样位置曾切换又返回。与此同时，$D_g^{CHP}$ 从 40% 的约 717.86 降到 45% 的约 684.94 MWh，价格与自调度机会盈余随之变化。40%→45% 时，物理暴露固定约 760.10 MWh，$\delta D_g^{UC}$ 增加约 1595.52 美元，$M_g^{rep,CHP}$ 下降约 6.53 美元，利润于是回升约 1588.99 美元。40%→42.5% 的自调度小时出力发生变化；42.5%→45% 的所选自调度轨迹相同。物理执行稳定**不等于**凸化定价或反事实自调度稳定。

30-G1 的 40%、42.5%、45% 三点 CHP 价值分别约为 205806.82、206550.49、207269.78 美元；中点比两端价值的直线插值高约 **12.19 美元**，完整节点×小时价格中点与两端直线插值最大差约 **3.92 美元/MWh**。这些差异远大于本次价值/价格重求的数值误差，说明**整个 40%–45% 不能被一条仿射 value/所选 price 规律描述**；它并不定位精确折点数，也不证明利润过零点就是价值折点。

潮流同样需分层：30-G1、40%、第 30 条线路第 11 小时，物理 UC 潮流约 −1.07 MW，CHP 凸化 LP 潮流约 −20.8 MW、恰在下限，CHP 线路对偶约 −1.33。线路对偶与**凸化**潮流互补，不能用物理潮流审查它。这个差异是价格形成与执行分离的可解释例子，尚不足以单独断言它造成了该机组的利润回升。

对最关键的 30-G1 40%、45% 两点，另用 simplex、barrier+crossover 与默认 barrier without crossover 重算所选 CHP 对偶并重新结算。三种算法的完整价格向量最大差约 **0.0309 美元/MWh**，目标机组利润差不足 **0.00013 美元**，上述利润符号与 CHP/LMP 对照保持不变。这是关键结论的算法选择稳健性，不证明对偶价格唯一。

30 节点仅放松线路限额的配对控制中，G1 在 40% 的 CHP 增量利润约 +1319 美元、45% 约 −3368 美元；获利方向变化没有因消除该设置下的拥塞而消失，网络条件却改变了翻转位置和幅度。因此更稳妥的主张是**网络调节激励**，不是“拥塞是利润翻转的必要原因”。

## 参数化方法的实际进度与论文取舍

原有 6-G2 的 $\delta\in[0,0.1]$ 五段 value 结果仍是经过多档容差验证的窄区间方法原型；它不覆盖本次 4%–10% 的经济窗口。新探针在该窗口的五个点审计了最优面左右暴露，最大实测 face 残差约 $5.002\times10^{-8}$ 美元，处于声明的 $10^{-7}$ 美元带宽内。30-G1 的 40%/42.5%/45% 三点也通过声明的 $10^{-5}$ 美元带宽，凸化暴露依次约为 717.86/686.65/684.94 MWh。**这是点态斜率证据，不是完整区间重构。** 对 6-G2 宽经济窗口尝试完整递归时触及 50 个求解点预算；不应盲目增加预算或把此现象解释为折点数的定论。

参数化 Oracle 下一步只需回答短窗口内**何处**出现定价层变化，以及给定价格选择能否在某个已验证区间内使用公式 (3)。在此之前，直接重求与恒等式 (1)–(2) 已足以支撑现象及定价规则反事实。论文应以“凸化定价层—物理执行层—自调度结算层的分离如何塑造可获利报价”为主线；Oracle 是辨别响应区间的分析工具，而非当前已完成的全域利润预测器。

## 可复现材料

统一入口为 `run_matched_pricing_experiment.py`。每个报价点只求一次物理 UC，并保存 `summary.csv`、全机组 `physical_schedule.csv`（含对应 CHP 凸化调度）、目标机组 `target_hourly.csv`、全节点 `nodal_prices.csv`、CHP 活动线路 `active_lines.csv` 与两档右侧局部价格差分 `local_right_response.csv`。线路文件同时列物理/凸化潮流，程序检查后者与 CHP 线路对偶的互补性。`run_value_oracle.py --probe-deltas` 只审计指定报价点，不产生完整 regime 主张。

```powershell
python run_matched_pricing_experiment.py --case 6 --generator 1 --rho 0 0.04 0.05 0.06 0.07 0.08 0.10 --out-dir results/matched_6_G2_tight
python run_matched_pricing_experiment.py --case 30 --generator 0 --rho 0 0.38 0.40 0.425 0.45 0.47 0.50 --out-dir results/matched_30_G1_tight
python run_matched_pricing_experiment.py --case 30 --generator 0 --rho 0 0.40 0.45 --congestion relaxed --out-dir results/matched_30_G1_relaxed
python run_matched_pricing_experiment.py --case 30 --generator 0 --rho 0 0.40 0.45 --chp-method 1 --crossover 1 --out-dir results/matched_30_G1_simplex
python run_matched_pricing_experiment.py --case 30 --generator 0 --rho 0 0.40 0.45 --chp-method 2 --crossover 1 --out-dir results/matched_30_G1_barrier_crossover
python run_value_oracle.py --case 6 --generator 1 --probe-deltas 0.479995 0.59999375 0.7199925 0.83999125 1.1999875 --face-tolerance 1e-7 --out-dir results/value_probe_6_G2_economic
python run_value_oracle.py --case 30 --generator 0 --probe-deltas 16.7928 17.84235 18.8919 --face-tolerance 1e-5 --out-dir results/value_probe_30_G1_economic
```
