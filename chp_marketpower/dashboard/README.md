# CHP Oracle Explorer

这是把既有参数优化结果接成可操作研究工具的本地工作台，不改变主算法、已有选价路径或论文图表。当前版本扩展30节点报价方向、全天UC区域、已验证映射自动注册及按需加载，并增加方法解释与数值验证页面。报价仍为一个预先声明的一维方向：

\[
c(\delta)=c^0+\delta d,\qquad \delta=\rho\,c_{\rm ref},\quad 0\leq\rho\leq 0.5.
\]

指定机组的全部 PWL 增量段加同一绝对加数，可作用于全天或某一小时；空载、启停费用不变。不能将此控制理解为任意 24 维报价，也不能直接改变负荷、线限或初态而复用旧图。

## 立即打开

从 `chp_marketpower` 目录运行：

```powershell
python -m streamlit run dashboard/app.py --server.address 127.0.0.1 --server.port 8501 --server.headless true --server.fileWatcherType poll --browser.gatherUsageStats false
```

浏览器访问 **http://127.0.0.1:8501**。已有 Streamlit、Plotly、NumPy、Pandas 即可运行价格/存档展示；点击按需结算需要本机 COPT 和 `gurobi_compat`。不另建 Web API，不开放公有求解端点，不接触许可证配置。

请从上述目录启动，以读取 `.streamlit/config.toml` 的统一浅色/青蓝主题。若使用过旧的 `fileWatcherType none` 启动命令，修改源代码后需要重启服务；只刷新浏览器可能仍使用旧编译缓存。主题配置改变后也应重启。

不便安装 Python 时，直接用浏览器打开 [exports/explorer.html](exports/explorer.html)。这个约 11 MB 的单文件已内嵌 Plotly 和所有演示数据，无 CDN、无数据请求、无 COPT 依赖，可以复制到另一台电脑离线演示。它不具备新的 UC/LOC 求解能力，未计算的利润明确显示 `not_available`。

## 建议的操作顺序

1. 选择30节点、G1、全天，先看0%真实报价。选择观察节点、小时和机组，查看完整价格、开停机、物理出力及成本/收入分解。
2. 在报价框输入 `31.451766098802286`%，或者选择对应 UC 阈值并跳转。此时有两套并列最优物理执行：区域3的 G1 利润为 **45100.8674** 美元，区域4为 **43713.5204** 美元。切换方案分别查看，不平均利润，不将乐观选取规则当作实际 ISO 规则。
3. 输入一个非样本报价，例如12.3456789%。CHP节点电价立即查询，机组组合与出力可查询已归档区域；结算若缺失，展开“计算机组组合与LOC结算（CHP电价已查询）”，设置时限后启动任务。独立进程显示进度，可以浏览或取消；完成后按精确报价、UC方案及版本缓存。
4. 换为 G1 第1小时，观察0%与50%：选价几乎不变，但46.6485636701%附近物理方案切换，50%时 G1 利润比真实报价减少约 **106.4152** 美元。
5. 切换118-G11全天，查看118×24价格矩阵及各节点响应。没有物理/结算缓存时不展示虚构值。累计时间页选择独立的 Q500 实验，看到 **Q=224** 的首次实测摊销。

接近 UC 边界的手工输入，在绝对 δ 距离 `1e-7` 内显式对齐存档边界，并披露请求报价与实际评估报价，避免小数输入舍入掩盖并列最优执行。负报价、超域和非有限输入拒绝查询。

## 三层计算，不混淆

- **P — `precomputed_verified`**：保存的完整节点×小时合法选价路径和最优价值。查表不解 LP；不证明 CHP 价格唯一。
- **U — `precomputed_verified` / `solved_on_demand`**：区域共同物理方案，或当前报价的全局物理 UC。检查二元状态、平衡、容量、爬坡、最小启停时间及线限。没有 UC 时绝不以凸化 CHP 出力替代。
- **S — `sampled_only` / `solved_on_demand`**：在当前精确报价与指定物理方案下已有的直接结算样本，或新解的全机组申报自调度。利润不插值。收入 + 申报 LOC − 真实成本 = 真实利润；该结算是研究规则，不是完整实际市场法规模型。

求解中的阶段反馈在本地页面显示；本版是单用户串行工作台，不另造后台集群。实时缓存存于 `results/dashboard_runtime_cache`，不自动发布。缓存键包含完整模型、选价版本、物理图、精确浮点报价、方案和计算代码；读取实时缓存也重新核对当前案例数据指纹。模型变化会拒绝旧实时缓存/求解；只读存档依然表示原来的固定场景。

## 页面、联动和计算反馈

- 首页并排展示战略机组的真实报价基准利润、当前真实总利润、相对基准额外利润与百分比。缺少任何必要结果显示“待计算”，不以零替代。百分比为额外利润 / |基准利润|；基准接近零时不定义百分比。
- P/U/S 三栏分别解释即时查表、存档/直接物理执行、精确结算来源。“请求报价”和“实际评估报价”同时显示，边界对齐不再隐藏在一行技术文字中。
- “研究视图”只绘制当前页。价格页增加固定节点的报价×小时、固定小时的报价×节点热图；网格含全部选价折点及均匀采样，纯用于显示，不增加求解或区域证明。
- 观察机组、节点、小时在各页共享。切换观察机组会联动其节点；仍可独立选择任意观察节点。结算表选行同样更新观察机组及节点。更换系统、战略机组或报价方向时重置观察上下文。
- 候选利润图默认额外利润并画零参考线，可切换真实总利润；仍只画已有报价/物理方案候选，不拟合连续利润。所有变化热图红色为上涨/增加、蓝色为下降/减少；价格容差单位为 $/MWh，价值为 USD。
- 物理参数、初态与增量成本分段分成两张可读表；完整 JSON/PTDF/线限保留下载，不因页面简化而删数据。

UC/LOC 在独立本机子进程运行，不占住页面脚本。每个浏览器会话最多一个活动任务，默认600秒，可设置1–3600秒。取消或超时终止该进程，只有全部机组结算完成且原有最优/物理/会计检查通过，才原子发布该精确报价缓存。失败可重试；已完成的真实报价基准缓存可以复用。超时前若基准已完整完成，它仍是合法缓存，不将未完成的当前报价标为成功。

任务声明原场景、报价、物理方案与版本；运行时切换报价/页面不会把任务结果错误挂到新报价。页面及工作进程各自有时限保护，关闭浏览器或重启服务后，遗留子进程也不会无期限运行。任务日志/进度位于本机 `results/dashboard_jobs`，不自动发布。Windows短暂文件占用采用有界重试；并行写缓存使用独立临时文件后原子替换。

离线页同步提供摘要、联动、惰性视图、时空响应与成本表，但不提供进程、取消或新的实时结算。118节点的本机实时缓存不会偷偷混进离线价格档案。

## 数据导出与追溯

已经附带一份验证后的导出，普通展示不需要再次导出。如果重新生成，必须在拥有原始见证的研究机器执行：

```powershell
python -m dashboard.export --refresh
```

导出检查原始见证与 compact 数组、审计与模型身份绑定；全天结算额外核对经济来源记录的原始/compact/物理方案哈希。所有存档结算进一步逐行核对当前展示价格下的能量收入、物理方案真实成本、利润会计恒等式及自调度最优间隙；单小时端点同时核对初态审计的模型身份。

`manifest.json` 保留来源文件 SHA-256；`data.json` 保存完整模型参数、价格图、共同物理执行、精确结算样本及候选、计时流；`timing_summary.csv` 和 `timing_checkpoints.csv` 提供直接可用的计算表。浏览器可下载价格矩阵、查询结果、完整机组/负荷/PTDF/线限/初态与校验清单。

**核验发生在导出阶段，不是浏览器重新证明原始见证。SHA-256 是完整性和来源记录，不是数字签名或符号精确证书。** 旧地图模型绑定仍标注为事后代表点核对，不改写为历史同步快照。IEEE118的大型 `oracle.npz` 保留本机，不为演示新增上传。

## 受控扩充150个独立一维方向

先预览队列，不执行求解：

```powershell
python -m dashboard.precompute --case 30 --generators 1 2 3 4 5 6 --hours all
```

确认范围后显式执行，例如只尝试一个尚未完成的方向：

```powershell
python -m dashboard.precompute --case 30 --generators 3 --hours all --execute --max-tasks 1 --max-points 400 --seconds 600 --max-mb 1024
```

该入口复用 `run_affine_oracle.py`、`postprocess_oracle.py`、`validate_affine_oracle.py`，检查模型身份，跳过已发布/已验证图，保留逐点 checkpoint 和日志，可在相同预算参数下再次运行续算。每次限制任务数、每图总 CHP 点数、整个批次时间与该队列目录磁盘用量。总点数预算N最多分给发现阶段floor((N+1)/2)个见证点（含继承点），并为每个原始区间保留一次独立中点验证，因此发现与验证合计不超过N；不能把验证求解排除在预算外。时间/磁盘每秒检查一次，包含当前步骤的中止，可能有一个检查周期的超量。被中止的任务标为 `incomplete`，不会进入可查询目录；如中断破坏了写入中的 checkpoint，原生加载检查会拒绝，需在新目录重跑，不能手改为通过。

新任务记录于`results/dashboard_precompute`。构建完成后，原始见证、压缩数组、模型身份、完整范围、各原始区间的独立内部点及固定残差阈值全部核对通过，才自动发布到本地目录，不再手改`SOURCES`。独立验证记录必须绑定原始见证SHA-256和模型SHA-256。错误方向的检查点不能复用；完整原始检查点可重建失配的压缩文件。失败/中断保留诊断，不作为已发布结果。

完整30节点单小时队列，可重复运行以跳过已发布方向：

```powershell
python -m dashboard.precompute --case 30 --generators 1 2 3 4 5 6 --hours (1..24) --execute --max-tasks 144 --max-points 400 --seconds 1800 --max-mb 4096
```

全天UC区域扩展复用原有共同最优方案/端点全局下界算法，不启动利润扫描：

```powershell
python -m dashboard.precompute --case 30 --generators 1 2 3 4 5 6 --hours all --uc-only --execute --max-tasks 6 --max-uc-solves 400 --seconds 1200 --max-mb 1024
```

`--seconds`限制整个批次。UC区域仅在全域覆盖、物理可行性、端点全局最优间隙、原始价格/模型版本一致时发布。并列最优边界分别保留相邻方案，不默认选择利润较高的方案。部分UC档案保留在原目录，不强行发布或覆盖；需检查失败原因后在新目录重新运行原生脚本。

## 按需读取、零加价基准与版本

`catalog.json`只保存方向索引及摘要；共享模型/计时文件与每个场景分别保存，文件以内容哈希命名。页面仅加载所选场景，目录最后原子更新，批处理与导出共用跨进程发布锁。重新导出精选案例不会删除已注册扩展或同一选价路径下已发布的UC区域。离线HTML仍只有四个精选方向，不把150张图全部内嵌进去。

各方向都相对于自己的零加价选价计算电价变化和利润增量。注册时记录该基准与30-G1全天参考路径的最大电价差；不通过改写端点价格来强行统一。即使基准电价相同，也不意味着UC并列方案或补偿规则自动统一，跨方向利润排名仍需声明共同规则。旧论文选价路径不改变。

后台请求同时绑定模型、选价、UC区域版本与计算代码；版本改变的旧任务不能用于新场景。独立验证结果也只有在报价、模型和选价版本全部匹配时才显示在当前结果下。

## 方法与数值验证页面

“方法与理论依据”解释固定可行域的参数化CHP LP、凹分段仿射目标值、共同原始最优解和完整对偶插值。交互例子读取当前方向的真实原始最优性区间及节点电价；θ滑块只演示插值，不改变左侧申报价。不能只插值两个价格点，也不能由目标值仿射推断实际机组组合不变。

“数值验证”展示原始可行性、完整对偶符号/驻点/互补残差、原始—对偶目标间隙、节点电价投影及独立目标值核对，连同模型/选价/原始见证版本。**直接求解器返回不同合法对偶价格不是失败判据。** 点击“独立验证当前报价的CHP”才另行求解，默认120秒，可取消；该操作不运行UC或LOC，也不覆盖原归档。

原始命名`price_tolerance_usd`实际约束的是共同原始解的**目标值间隙（USD）**，不是节点电价误差。界面已改正；电价共线压缩容差为USD/MWh，节点电价投影、驻点和互补等另列阈值。旧CLI/JSON键保留以兼容既有检查点。

## 电力系统术语与能力边界

界面统一采用：CHP节点电价、网络约束机组组合（UC）、机组启停状态、机组出力计划、电能量市场收入、基于申报成本的机会成本损失（LOC）补偿、实际运行成本、机组利润及利润增量。仅有基态PTDF线限，不宣称含N−1校核的安全约束机组组合。功率用MW，发电量用MWh，边际报价和电价用USD/MWh，成本/收入/利润及目标值间隙用USD；本研究各时段为1h。

当前并未完成“任意报价下全部经济结果”的离线Oracle。六个全天方向可以查询已验证UC方案，但新报价的LOC/利润通常仍需自调度；单小时方向优先保证CHP电价查询。后续才是固定仿射电价段内的自调度最大申报盈余映射，不用利润样本插值代替。
